# TypeScript

> Fastnode is TypeScript-first: write your config, handlers, and server code in TypeScript with zero setup.

Fastnode is written in TypeScript and bundles your server code, so `.ts` files work out of the box in development and production, with no separate compile step. The TypeScript compiler is only needed for type checking (for example `tsc --noEmit` in CI).

All public utilities ship with types:

```ts [fastnode.config.ts]
import { defineConfig } from "fastnode";

export default defineConfig({
  // Fully typed config with completions
});
```

```ts [server/routes/hello.ts]
import { defineHandler } from "fastnode";

export default defineHandler((event) => {
  return { hello: "world" }; // Typed event and inferred return type
});
```

Types (such as `FastnodeConfig`, `FastnodeModule`, or `FastnodeRuntimeConfig`) are exported from `fastnode/types`:

```ts
import type { FastnodeModule } from "fastnode/types";
```

## `tsconfig.json` setup

Fastnode provides a shareable TypeScript configuration you can extend from:

```json [tsconfig.json]
{
  "extends": "fastnode/tsconfig"
}
```

It enables modern, strict defaults matching how Fastnode bundles your code: `strict` type checking, bundler module resolution, `noEmit`, `verbatimModuleSyntax`, and `allowImportingTsExtensions` (so you can use explicit `.ts` extensions in imports). You can override any option by adding your own `compilerOptions` on top:

```json [tsconfig.json]
{
  "extends": "fastnode/tsconfig",
  "compilerOptions": {
    "jsx": "react-jsx"
  }
}
```

## `typescript` config options

| Option | Default | Description |
| --- | --- | --- |
| `tsConfig` | Project `tsconfig.json` | TypeScript config used by the bundler for JSX options and path aliases. |
| `tsconfigPaths` | `true` | Resolve path aliases (`compilerOptions.paths`) of `tsConfig` for the server sources. |

Fastnode reads your project's root `tsconfig.json` to pick up JSX settings (`jsx`, `jsxFactory`, `jsxFragmentFactory`, `jsxImportSource`) and path aliases (`compilerOptions.paths`). Set `typescript.tsConfig` to override it:

```ts [fastnode.config.ts]
import { defineConfig } from "fastnode";

export default defineConfig({
  typescript: {
    tsConfig: {
      compilerOptions: {
        jsx: "react-jsx",
      },
    },
  },
});
```

### Path aliases

Path aliases (`compilerOptions.paths`) are resolved for your server sources with every builder and with `builder: false`, including those inherited with `extends`.

- The [`alias`](/config/build#alias) option (and Vite's `resolve.alias`) takes precedence over path aliases.
- Paths to declaration files (`.d.ts`) are ignored, the import keeps its regular resolution.
- With the Vite builder, they apply to the Fastnode environment only. Enable Vite's [`resolve.tsconfigPaths`](https://vite.dev/config/shared-options#resolve-tsconfigpaths) option for the other environments. In development, patterns starting with `*` do not apply to installed packages.
- Set `typescript.tsconfigPaths: false` to disable them.
