# Server Utilities

> A reference of everything you can import from `fastnode` and its subpaths in your server code.

Fastnode has **no auto-imports**: every utility must be explicitly imported from the main `fastnode` entry or one of its subpaths. This page maps each export to its import path.

## Quick reference

| What you want to do | Import |
| --- | --- |
| Define an event handler | `import { defineHandler } from "fastnode"`{lang=ts} |
| Define a middleware | `import { defineMiddleware } from "fastnode"`{lang=ts} |
| Throw an HTTP error | `import { HTTPError } from "fastnode"`{lang=ts} |
| Read the body, query, cookies, ... | `import { readBody, getQuery } from "fastnode/h3"`{lang=ts} |
| Call your own routes internally | `import { serverFetch } from "fastnode"`{lang=ts} |
| Handle WebSocket connections | `import { defineWebSocketHandler } from "fastnode"`{lang=ts} |
| Add a runtime plugin | `import { definePlugin } from "fastnode"`{lang=ts} |
| Customize the error response | `import { defineErrorHandler } from "fastnode"`{lang=ts} |
| Cache a handler or function | `import { defineCachedHandler, defineCachedFunction } from "fastnode/cache"`{lang=ts} |
| Read/write key-value storage | `import { useKV } from "fastnode/kv"`{lang=ts} |
| Query a SQL database | `import { useDatabase } from "fastnode/database"`{lang=ts} |
| Access runtime config | `import { useRuntimeConfig } from "fastnode/runtime-config"`{lang=ts} |
| Define and run tasks | `import { defineTask, runTask } from "fastnode/task"`{lang=ts} |
| Access the app instance and hooks | `import { useFastnodeApp, useFastnodeHooks } from "fastnode/app"`{lang=ts} |
| Configure Fastnode (`fastnode.config.ts`) | `import { defineConfig } from "fastnode"`{lang=ts} |
| Use Fastnode as a Vite plugin | `import { fastnode } from "fastnode/vite"`{lang=ts} |

## `fastnode`

The main entry contains everything you need for day-to-day route handlers.

| Export | Description |
| --- | --- |
| `defineHandler` | Define an event handler for a [route or middleware file](/docs/routing). |
| `defineMiddleware` | Define a [middleware](/docs/routing#middleware) that runs before route handlers. |
| `defineWebSocketHandler` | Define a [WebSocket handler](/docs/websocket) for a route file. |
| `definePlugin` | Define a [runtime plugin](/docs/plugins) that runs on server startup. |
| `defineErrorHandler` | Define a custom [error handler](/config/routing#errorhandler) to replace the built-in error page. |
| `defineConfig` | Define Fastnode [configuration](/docs/configuration) (used in `fastnode.config.ts`, not in runtime code). |
| `defineRouteMeta` | Attach route metadata such as [OpenAPI specs](/docs/openapi) (build-time macro). |
| `HTTPError` | Throw HTTP errors with a status code: `throw new HTTPError("Not found", { status: 404 })`{lang=ts}. |
| `HTTPResponse` | Return a body with a custom status and headers from a handler. |
| `html` | Tagged template literal returning an HTML response (`text/html` content type). |
| `serverFetch` | Call your own routes internally, without a network round-trip. |
| `fetch` | Like global `fetch`, but paths starting with `/` are routed to your own server. |

Commonly used types are also exported: `H3Event`, `EventHandlerRequest`, and `EventHandlerWithFetch`.

```ts [server/routes/hello.ts]
import { defineHandler, HTTPError } from "fastnode";

export default defineHandler((event) => {
  const name = event.url.searchParams.get("name");
  if (!name) {
    throw new HTTPError("Missing name", { status: 400 });
  }
  return { hello: name };
});
```

### Internal fetch

`serverFetch` calls a route of your own app directly: the request goes through the Fastnode app (route rules, middleware, plugins) without touching the network:

```ts [server/routes/summary.ts]
import { defineHandler, serverFetch } from "fastnode";

export default defineHandler(async () => {
  const res = await serverFetch("/api/stats"); // returns a web Response
  return { stats: await res.json() };
});
```

The `fetch` export is a universal variant: absolute paths (starting with `/`) are handled internally via `serverFetch`, everything else falls back to global `fetch`:

```ts
import { fetch } from "fastnode";

await fetch("/api/hello"); // handled by your own server
await fetch("https://example.com"); // regular network fetch
```

### Error handler

Point the [`errorHandler` config](/config/routing#errorhandler) to a file that exports a custom error handler:

```ts [error.ts]
import { defineErrorHandler } from "fastnode";

export default defineErrorHandler((error, event) => {
  return new Response(`[custom error] ${error.message}`, {
    status: error.status,
    headers: { "Content-Type": "text/plain" },
  });
});
```

### Runtime plugins

Plugins run once on server startup and can hook into the [runtime lifecycle](/docs/lifecycle):

```ts [server/plugins/log.ts]
import { definePlugin } from "fastnode";

export default definePlugin((fastnodeApp) => {
  fastnodeApp.hooks.hook("request", (event) => {
    console.log("request:", event.url.pathname);
  });
});
```

See the [plugins guide](/docs/plugins) for more.

## `fastnode/h3`

Re-exports all [H3 v2](https://h3.dev) utilities: `readBody`, `getQuery`, `getCookie`, `setCookie`, `proxy`, `redirect`, and many more.

```ts [server/routes/form.post.ts]
import { defineHandler } from "fastnode";
import { readBody, getCookie } from "fastnode/h3";

export default defineHandler(async (event) => {
  const body = await readBody(event);
  const session = getCookie(event, "session");
  return { body, session };
});
```

::note
See the [H3 utilities documentation](https://h3.dev/utils) for the full list.
::

## `fastnode/cache`

| Export | Description |
| --- | --- |
| `defineCachedHandler` | Wrap an event handler with caching. |
| `defineCachedFunction` | Cache the result of any (async) function. |

```ts
import { defineCachedHandler } from "fastnode/cache";

export default defineCachedHandler(() => `Generated at ${new Date().toISOString()}`, {
  maxAge: 60,
});
```

See the [cache guide](/docs/cache) for options, cache keys, and invalidation.

## `fastnode/kv`

| Export | Description |
| --- | --- |
| `useKV` | Access the key-value [storage layer](/docs/storage), optionally scoped to a base (e.g. `useKV("data")`{lang=ts}). |

```ts
import { useKV } from "fastnode/kv";

await useKV("data").set("visits", 42);
```

See the [KV storage guide](/docs/storage) for mountpoints and drivers.

::note
`useStorage` from `fastnode/storage` still works as a deprecated alias of `useKV`.
::

## `fastnode/database`

| Export | Description |
| --- | --- |
| `useDatabase` | Access a configured SQL [database](/docs/database) connection (default: `useDatabase()`{lang=ts}, named: `useDatabase("users")`{lang=ts}). |

```ts
import { useDatabase } from "fastnode/database";

const db = useDatabase();
const { rows } = await db.sql`SELECT * FROM users`;
```

See the [database guide](/docs/database) for connectors and configuration.

## `fastnode/runtime-config`

| Export | Description |
| --- | --- |
| `useRuntimeConfig` | Access [runtime configuration](/docs/configuration#runtime-configuration), overridable with `FASTNODE_*` environment variables. |

```ts
import { useRuntimeConfig } from "fastnode/runtime-config";

const { apiToken } = useRuntimeConfig();
```

## `fastnode/task`

| Export | Description |
| --- | --- |
| `defineTask` | Define a [task](/docs/tasks) in a `server/tasks/` file. |
| `runTask` | Run a task by name from anywhere in your server code. |

```ts
import { runTask } from "fastnode/task";

const { result } = await runTask("db:migrate", { payload: { force: true } });
```

See the [tasks guide](/docs/tasks). Tasks are experimental and require the `experimental.tasks` flag.

## `fastnode/app`

Lower-level access to the running Fastnode app.

| Export | Description |
| --- | --- |
| `useFastnodeApp` | Access the current [Fastnode app instance](/docs/lifecycle) (`fetch`, `hooks`, ...). |
| `useFastnodeHooks` | Access the [runtime hooks](/docs/plugins#fastnode-runtime-hooks) instance to register hooks outside of plugins. |
| `getRouteRules` | Get the resolved [route rules](/docs/routing#route-rules) for a method and pathname: `getRouteRules("GET", "/blog/post")`{lang=ts}. |
| `serverFetch`, `fetch` | Same as the [main entry exports](#internal-fetch). |

```ts
import { useFastnodeHooks } from "fastnode/app";

useFastnodeHooks().hook("error", (error) => {
  console.error(error);
});
```

## `fastnode/context`

| Export | Description |
| --- | --- |
| `useRequest` | Access the current request from anywhere within the request lifecycle, without passing `event` around. |

```ts
import { useRequest } from "fastnode/context";

const request = useRequest();
```

::warning
`useRequest` is experimental: it requires the `experimental.asyncContext: true`{lang=ts} config flag and only works on runtimes with `AsyncLocalStorage` support (Node.js and compatible runtimes).
::

## `fastnode/config`

| Export | Description |
| --- | --- |
| `defineConfig` | Same as the `defineConfig` export from the main `fastnode` entry (also exported as the deprecated `defineFastnodeConfig` alias). |

Prefer importing `defineConfig` from `"fastnode"` directly.

## `fastnode/types`

Type-only entry with all public Fastnode types, including `FastnodeConfig`, `Fastnode`, `FastnodeApp`, `FastnodeAppPlugin`, `FastnodeErrorHandler`, `FastnodeRuntimeConfig`, `FastnodeRuntimeHooks`, and `Task`.

```ts
import type { FastnodeRuntimeConfig } from "fastnode/types";
```

## `fastnode/vite`

| Export | Description |
| --- | --- |
| `fastnode` | The Fastnode [Vite plugin](/docs/vite). |

```ts [vite.config.ts]
import { defineConfig } from "vite";
import { fastnode } from "fastnode/vite";

export default defineConfig({
  plugins: [fastnode()],
});
```

The `FastnodePluginConfig` and `ViteServiceConfig` types are also exported. See the [Vite integration guide](/docs/vite).

## `fastnode/builder`

Programmatic API for tools that drive Fastnode without the CLI (build wrappers, framework integrations).

| Export | Description |
| --- | --- |
| `createFastnode` | Create a Fastnode instance from an inline config (and `fastnode.config` in `rootDir`). |
| `loadOptions` | Load and resolve Fastnode options without creating an instance. |
| `prepare` | Clean the output directories. |
| `copyPublicAssets` | Copy public assets to the output directory. |
| `prerender` | Prerender routes. |
| `build` | Build the server bundle. |
| `createDevServer` | Create a development server for a Fastnode instance (returns `{ fetch, upgrade, listen, reload, close }`). |
| `getBuildInfo` | Read `fastnode.json` of the last build (accepts `{ rootDir, outputDir }`). |
| `startPreview` | Start an in-process preview of a build (`{ rootDir, outputDir?, loader? }` returns `{ fetch, upgrade?, close }`). |
| `deploy` | Run the deploy command of the preset for an existing build (`deploy(fastnode, { args? })`). |

```ts
import { build, copyPublicAssets, createFastnode, deploy, prepare, prerender } from "fastnode/builder";

const fastnode = await createFastnode({ rootDir: ".", dev: false, preset: "cloudflare_module" });
await prepare(fastnode);
await copyPublicAssets(fastnode);
await prerender(fastnode);
await build(fastnode);
await deploy(fastnode, { args: ["--env", "staging"] });
await fastnode.close();
```

`deploy` uses `commands.deploy` from the resolved options. It is either a shell command (run from `rootDir`, with `./` paths rewritten to the output directory) or a function for presets that deploy programmatically (such as `zephyr`). Presets that lack a deploy command throw an error.

## Other entries

The remaining subpaths (`fastnode/meta` for the package `version`, `runtimeDir` and `runtimeDependencies`, `fastnode/vite/runtime`, `fastnode/tsconfig`) are internal and rarely needed in application code.
