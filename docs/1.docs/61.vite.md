# Vite Integration

> Use Fastnode as a Vite plugin to build full-stack applications, and choose the builder that bundles your server.

Fastnode integrates with [Vite](https://vite.dev) as a plugin. Adding it to a Vite project gives you a full server alongside your frontend: API routes, server-side rendering, and a production build that deploys anywhere.

## Fastnode as a Vite plugin

Add the plugin to your Vite config:

```ts [vite.config.ts]
import { defineConfig } from "vite";
import { fastnode } from "fastnode/vite";

export default defineConfig({
  plugins: [fastnode()],
});
```

With the plugin enabled, you use the Vite CLI for everything:

- **`vite dev`**: One dev server for both frontend and backend. Fastnode serves your server routes and assets while Vite handles client modules. Server code runs in an isolated worker and automatically reloads when server files change, while client code keeps Vite's hot module replacement (HMR).
- **`vite build`**: Builds the client and the server together into a single deployable `.output/` directory, using any [deployment preset](/deploy).
- **`vite preview`**: Serves the production build locally through Fastnode, including static assets and WebSocket support.

::tip
Follow the [quick start](/docs/quick-start#add-to-a-vite-project) for a step-by-step guide to adding Fastnode to an existing Vite project.
::

::note
When using the Vite plugin, prefer `vite dev` over `fastnode dev`; the Fastnode CLI dev server does not support the Vite builder. `fastnode build` works and runs the Vite build under the hood.
::

## Frontend frameworks

The Fastnode plugin composes with other Vite plugins, so you can use your favorite frontend framework for server-side rendering with client hydration:

```ts [vite.config.ts]
import { defineConfig } from "vite";
import { fastnode } from "fastnode/vite";
import react from "@vitejs/plugin-react";

export default defineConfig({
  plugins: [fastnode(), react()],
});
```

Fastnode automatically detects a file named `entry-server.(ts|js|tsx|jsx|mjs)` (in the project root, `app/`, `src/`, or the server directory) and uses it as the SSR entry.

Instead of re-explaining each setup, see the working examples:

- [SSR with React](/examples/vite-ssr-react)
- [SSR with Vue Router](/examples/vite-ssr-vue-router)

Learn more about how unmatched routes are rendered in the [renderer](/docs/renderer) and [server entry](/docs/server-entry) guides.

## Configuring Fastnode with Vite

Fastnode configuration can live in three places, all accepting the same [options](/config):

1. A `fastnode.config.ts` file (recommended for most projects)
2. The `fastnode` key in your Vite config
3. Inline plugin options passed to `fastnode()`

::code-group
```ts [fastnode.config.ts]
import { defineConfig } from "fastnode";

export default defineConfig({
  serverDir: "./server",
});
```
```ts [vite.config.ts (fastnode key)]
import { defineConfig } from "vite";
import { fastnode } from "fastnode/vite";

export default defineConfig({
  plugins: [fastnode()],
  fastnode: {
    serverDir: "./server",
  },
});
```
```ts [vite.config.ts (inline)]
import { defineConfig } from "vite";
import { fastnode } from "fastnode/vite";

export default defineConfig({
  plugins: [
    fastnode({
      serverDir: "./server",
    }),
  ],
});
```
::

Inline plugin options take precedence over the `fastnode` key in the Vite config, and both override `fastnode.config.ts`. The `dev` mode and `rootDir` are inferred from Vite and cannot be overridden.

Vite plugins can also extend Fastnode programmatically by exposing a `fastnode` key (a [Fastnode module](/docs/modules)) on the plugin object. See the [Vite Fastnode plugin example](/examples/vite-fastnode-plugin).

### Using a specific Vite package

Fastnode does not depend on `vite` itself. The `fastnode/vite` plugin uses the `vite` package that runs it, and the `vite` builder (`fastnode build`) resolves the one installed in your project. To use another `vite` package, pass it with the `vite.path` option:

```ts
import { createServer } from "vite";
import { fastnode } from "fastnode/vite";

const server = await createServer({
  plugins: [fastnode({ vite: { path: import.meta.resolve("vite") } })],
});
```

The option accepts a path or `file://` URL to the `vite` package directory or entry.

### Vite options

Vite-specific options are set under the `vite` key. Like other options, they can be passed to the plugin, set under `fastnode` in the Vite config, or in `fastnode.config.ts`:

```ts [fastnode.config.ts]
import { defineConfig } from "fastnode";

export default defineConfig({
  vite: {
    serverReload: false,
  },
});
```

::field{name="services" type="Record<string, { entry: string }>"}
Register additional server environments as fetchable services. Server environments with an entry (such as `ssr`) are registered automatically.
::

::field{name="assetsImport" type="boolean"}
Enable `?assets` imports for collecting CSS and JS assets from entry points (default: `true`).
::

::field{name="serverReload" type="boolean"}
Reload the server (and browser) when a server-only module changes (default: `true`).
::

## Testing with Vitest

[Vitest](https://vitest.dev) picks up the `fastnode()` plugin from your Vite config and runs your tests against the Fastnode runtime. See the [testing guide](/docs/testing) for setup and details.

## Builders

Fastnode can bundle your server with one of three builders:

| Builder | Description |
| --- | --- |
| `rolldown` | Default. Rust-based bundler. Requires `rolldown` to be installed (installed on demand when building). |
| `rollup` | Battle-tested bundler with a mature plugin ecosystem. Requires `rollup` to be installed. |
| `vite` | Full-stack builds via the Vite plugin. Requires `vite` to be installed. |

### How the builder is selected

The builder is resolved in this order:

1. The `builder` option in your Fastnode config.
2. The `FASTNODE_BUILDER` environment variable.
3. Auto-detection: if `vite` is installed and your `vite.config` uses the `fastnode()` plugin, the `vite` builder is used.
4. Otherwise, Fastnode defaults to `rolldown`. If `rolldown` is not installed (and no `rollupConfig` or `rolldownConfig` is set), `fastnode dev` runs the server sources without a builder ([`builder: false`](/config/build#builder)) and `fastnode build` offers to install it.

```ts [fastnode.config.ts]
import { defineConfig } from "fastnode";

export default defineConfig({
  builder: "rollup",
});
```

Or without touching the config file:

```bash
FASTNODE_BUILDER=rollup fastnode build
```

If you explicitly select `rollup` or `vite` and the package is not installed, Fastnode prompts to install it as a dev dependency. `rolldown` is installed the same way when building.

The `vite` builder prerenders routes with `rolldown` (resolved from your project or your `vite`). Without it (e.g. with Vite 7), the prerenderer runs the server sources without a builder.

### Which builder to pick

- Stick with **`rolldown`** for standalone servers and APIs. It is the fastest option.
- Pick **`rollup`** if you depend on Rollup-specific plugins or need maximum ecosystem compatibility.
- Use **`vite`** (usually via auto-detection) whenever you have a frontend built with Vite. It is the only builder that bundles client and server together.

### Customizing the bundler

To add build plugins for every builder (including `vite`, and `builder: false`), use [`buildPlugins`](/config/build#buildplugins). With `vite`, they apply to the server bundle (`fastnode` environment) as bundler plugins, after Vite's own plugins; use Vite's `plugins` for Vite plugins.

```ts [fastnode.config.ts]
import { defineConfig } from "fastnode";
import myPlugin from "./my-plugin";

export default defineConfig({
  buildPlugins: [myPlugin()],
});
```

For advanced cases, you can pass extra configuration directly to the underlying bundler with `rollupConfig` or `rolldownConfig`:

```ts [fastnode.config.ts]
import { defineConfig } from "fastnode";

export default defineConfig({
  rolldownConfig: {
    // Extra Rolldown options and plugins
  },
  rollupConfig: {
    // Extra Rollup options and plugins
  },
});
```

Each option applies to its matching builder. With the `vite` builder, both are merged into the server bundle configuration depending on whether Vite runs on Rolldown (`rolldown-vite`) or Rollup.

::warning
These options are escape hatches. Prefer built-in Fastnode options when available, as low-level bundler overrides can break across builders.
::

## Good to know

- **Server reloads instead of HMR**: changes to server-only modules trigger a server reload (and a browser refresh) rather than hot module replacement. Modules shared between client and server keep normal Vite HMR.
- **Dev server port**: the port is resolved from the `PORT` environment variable, then Vite's `server.port`, then Fastnode's `devServer.port` (default: `3000`).
- **Environment files**: in both dev and build, Fastnode loads `.env`, `.env.local`, and mode-specific variants (`.env.[mode]`, `.env.[mode].local`) following [Vite conventions](https://vite.dev/guide/env-and-mode#env-files). Existing environment variables take precedence over `.env` values.
- **Vite environments**: Fastnode uses the [Vite environment API](https://vite.dev/guide/api-environment) and registers `client` and `fastnode` environments (plus `ssr` when an SSR entry exists). You can configure the client entry point via `environments.client.build.rollupOptions.input` in your Vite config, as shown in the [SSR examples](/examples/vite-ssr-react).
